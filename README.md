# Reading AI-Written Code

A beginner-friendly, plain-English manual for **getting code written by an AI — and using it safely**
even if you cannot write code yourself: what code actually does, how to read it like an informed
editor, spotting the "trust me" moments, asking what could break, testing before you rely on it,
keeping originals safe, checking secrets and paths, and the book's core loop — the
**copy-run-rollback routine**.

Eleven chapters (a welcome plus ten) end with an annotated walkthrough of a real, runnable example
script (`examples/walkthrough/safe_rename.py`, dry-run by default, tested by the test suite),
a one-page printable safety checklist, and a pocket glossary. Tables and checklists throughout;
no jargon left unexplained; and one rule on page one: *never let the first time you run something
be the time you actually need it.*

## Run the worked example yourself

The chapter-9 walkthrough annotates a real script that ships with the book. It renames
`IMG_4021.jpg`-style files to date-prefixed names, and it refuses to make changes by default:

```bash
python3 examples/walkthrough/safe_rename.py some-folder          # plan only
python3 examples/walkthrough/safe_rename.py some-folder --apply  # really rename
```

It never overwrites (collisions stop the plan), never ventures outside the folder you name,
and prints a count on every run. Chapter 9 explains every block of it in non-coder English.

## Build the site yourself (optional)

The built site lives in `site/`. To rebuild it after editing the chapters:

```bash
pip install -r requirements.txt   # installs the `markdown` package
python3 build.py                  # regenerates site/
```

## Run the tests

```bash
python3 -m unittest discover -s tests -v
```

The test suite verifies book structure and length, markdown-to-HTML conversion (headings, tables,
fenced code, checkbox styling, link rewriting), the generated site (files, navigation, no external
assets), walkthrough/real-example consistency, the example script's safety behaviors (plan-only
default, idempotence, loud refusals, collision stops, no touching outside the folder), a privacy
sweep for secret-shaped strings, and the exact LICENSE line.

## Privacy-first by design

The build uses no network access, the site loads no external assets, and the test suite fails if
secret-shaped strings appear anywhere in the book, the example, or the built site. Repository
convention: no API keys, no personal data.
